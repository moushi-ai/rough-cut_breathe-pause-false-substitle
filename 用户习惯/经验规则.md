# 经验规则（机器学习产出，需人工确认）

> 本文件由「自进化学习」从你每次审核的 diff 中总结、**经你确认后**写入。
> 与手写的 `规则.md` **分开维护**：`规则.md` 是基线规则，本文件是从你真实剪辑里沉淀的个人偏好。
> 你可以随时直接编辑/删除任意一条，每条都带出处标签便于判断。
>
> **AI 在步骤 5.2 同时读 `规则.md` 和本文件。** 本文件的规则优先级不低于 `规则.md`，
> 冲突时以更具体、更新的为准。

## 维护约定（给执行学习的 AI 看）

1. 学习时**先读本文件全文**，再看本次 `review_log.json` 的 diff。
2. 只把能**泛化到下一条视频**的偏好写成规则；**不要**把单条视频的口误/语境例外固化成规则。
3. 对比「AI 为什么这么剪 vs 用户为什么这么剪」，抽象出通用判断，**宁可少写一条也不要写过窄的规则**。
4. 可做三种操作：**新增** / **细化已有** / **合并重复**；冗余、过时、矛盾的规则要收拾。
5. 每条规则带出处标签：`（学于 <视频名> YYYY-MM-DD；已确认）`。
6. **所有改动先列给用户确认，确认后才落盘**——不要直接写。
7. 若本次 diff 显示用户**违反了某条已有规则**，逐条提醒用户，让用户决定是「正当例外（规则不动）」还是「该把规则改松/加例外条件」。

## 规则正文

### 1. 自然语气词「啊」的保留

- 当「啊」在有效句子中承担强调、衔接或自然口播节奏时，默认保留；不得仅因它是单字或处于句首 / 句尾而删除。
- 仅删除独立成句、连续堆叠、明显卡顿，或删掉后语义、语气和节奏均不受影响的「啊」。
- 对临近切点的「啊」应回听：去掉后若使句子发顶、语气变急或衔接突兀，则保留。

（学于 飞书20260812-110516 2026-08-12；已确认）

### 2. 功能性「呢」的保留

- 当「呢」承担提问、反问、对照、上下文承接或自然口播节奏时，默认保留；不得仅因它是单字或处于句首 / 句尾而删除。
- 仅删除独立成句、连续堆叠、明显卡顿，且去掉后语义、语气和节奏均不受影响的「呢」。
- 对临近切点的「呢」应回听：删掉后若使问句、对照、承接或表达节奏变生硬，则保留。

（学于 飞书20260812-110516、飞书20260812-150445 2026-08-12；已确认）

### 3. 同句 / 邻句的“先草稿、后完整重说”

- 当先说出草稿、残句或较短表达，随后在同一句或相邻 1–3 句以相同主题更完整地重说时，按“删前保后”处理：确认后将前段作为删除候选，保留后一版。
- 词面重复只用于发现线索，不构成自动删除理由；必须同时确认后段更完整、能独立表达，且前段删除后不丢失有效信息。
- 普通重复、列举、固定说法、强调重复或语义不确定时，不打删除标。

（学于 飞书20260812-110516、飞书20260812-150445 2026-08-12；已确认）

### 4. 录制口令「321 / 三二一」的精确删除

- 将录制口令「321 / 三二一」视为强剪辑信号；即使它与正文黏连（如“321但问题是…”、“三二一好了…”），也只精确删除口令本身，保留紧随其后的有效正文。
- 不因口令与正文位于同一 ASR 片段就整句删除；必须使用逐字时间轴定位口令的精确 idx。

（学于 6月9日 印度 2026-08-12；已确认）

### 5. 以录制口令为界的重录簇整体清理

- 同一话题中出现「321 / 三二一」、连续两次及以上未完成表达，随后又出现一条连续且完整的重说时，将从第一次失败表达起、到最终完整版本前的全部内容视为一个重录簇：整簇预选删除，只保留最终完整版本。
- 「321 / 三二一」夹在两次近似表达之间时，是强重录分隔信号；后一版更完整且前一版不含独有信息时，即使两句并非紧邻，也按整簇删除处理。不得留下中间草稿、局部重说或倒计时。
- 规则 4 仍用于精确删除与正文黏连的口令本身。若后一版不能独立表达、前一版含独有信息，或语义无法确认，则不扩大删除范围，交由审核页决定。

- 仅在上下文唯一明确时做此类字幕纠错；对象存在歧义时保留 ASR 原文，并列入不确定清单，不凭主观猜测替换。
