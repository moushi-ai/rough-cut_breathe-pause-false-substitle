# 经验规则（机器学习产出，需人工确认）

> 本文件由「自进化学习」从你每次审核的 diff 中总结、**经你确认后**写入。
> 与手写的 `规则.md` **分开维护**：`规则.md` 是基线规则，本文件是从你真实剪辑里沉淀的个人偏好。
> 你可以随时直接编辑/删除任意一条，每条都带出处标签便于判断。
>
> **AI 在步骤 5.2 同时读 `规则.md` 和本文件。** 本文件的规则优先级不低于 `规则.md`，
> 冲突时以更具体、更新的为准。

## 维护约定（给执行学习的 AI 看）

1. 学习时**先读本文件全文**，再看本次 `review_log.json` 的 diff。
2. 只把能**泛化到下一条视频**的偏好写成规则；**不要**把单条视频的口误/语境例外固化成规则。
3. 对比「AI 为什么这么剪 vs 用户为什么这么剪」，抽象出通用判断，**宁可少写一条也不要写过窄的规则**。
4. 可做三种操作：**新增** / **细化已有** / **合并重复**；冗余、过时、矛盾的规则要收拾。
5. 每条规则带出处标签：`（学于 <视频名> YYYY-MM-DD；已确认）`。
6. **所有改动先列给用户确认，确认后才落盘**——不要直接写。
7. 若本次 diff 显示用户**违反了某条已有规则**，逐条提醒用户，让用户决定是「正当例外（规则不动）」还是「该把规则改松/加例外条件」。

## 规则正文

### 1. 自然语气词「啊」的保留

- 当「啊」在有效句子中承担强调、衔接或自然口播节奏时，默认保留；不得仅因它是单字或处于句首 / 句尾而删除。
- 仅删除独立成句、连续堆叠、明显卡顿，或删掉后语义、语气和节奏均不受影响的「啊」。
- 对临近切点的「啊」应回听：去掉后若使句子发顶、语气变急或衔接突兀，则保留。

（学于 飞书20260812-110516 2026-08-12；已确认）

### 2. 功能性「呢」的保留

- 当「呢」承担提问、反问、对照、上下文承接或自然口播节奏时，默认保留；不得仅因它是单字或处于句首 / 句尾而删除。
- 仅删除独立成句、连续堆叠、明显卡顿，且去掉后语义、语气和节奏均不受影响的「呢」。
- 对临近切点的「呢」应回听：删掉后若使问句、对照、承接或表达节奏变生硬，则保留。

（学于 飞书20260812-110516、飞书20260812-150445 2026-08-12；已确认）

### 3. 同句 / 邻句的“先草稿、后完整重说”

- 当先说出草稿、残句或较短表达，随后在同一句或相邻 1–3 句以相同主题更完整地重说时，按“删前保后”处理：确认后将前段作为删除候选，保留后一版。
- 词面重复只用于发现线索，不构成自动删除理由；必须同时确认后段更完整、能独立表达，且前段删除后不丢失有效信息。
- 同一句里即使后半段发生了重说，也不得把整句作为草稿删除。应定位到“开始重复／开始改口”的精确词级边界；边界之前若包含独有的动作、事实、人物状态或因果铺垫，必须保留。
- 普通重复、列举、固定说法、强调重复或语义不确定时，不打删除标。

（学于 飞书20260812-110516、飞书20260812-150445 2026-08-12；已确认；细化于 飞书20260812-150445 2026-08-13；已确认）

### 4. 录制口令「321 / 三二一」的精确删除

- 将录制口令「321 / 三二一」视为强剪辑信号；即使它与正文黏连（如“321但问题是…”、“三二一好了…”），也只精确删除口令本身，保留紧随其后的有效正文。
- 不因口令与正文位于同一 ASR 片段就整句删除；必须使用逐字时间轴定位口令的精确 idx。

（学于 6月9日 印度 2026-08-12；已确认）

### 5. 以录制口令为界的重录簇整体清理

- 同一话题中出现「321 / 三二一」、连续两次及以上未完成表达，随后又出现一段连续且完整的重说时，将从第一次失败表达起、到最终完整版本前的全部内容视为一个重录簇：整簇预选删除，只保留最终完整版本。
- 清理重录簇时，保留单位应是最后一段连续、完整、逻辑自洽的表达，而不是机械地只留时间轴上最后一句。若前一句为后一句提供必要的论述、指代、因果或修辞铺垫，两句应一起保留；只删除它们之前的草稿、残句和失败版本。
- 「321 / 三二一」夹在两次近似表达之间时，是强重录分隔信号；后一版更完整且前一版不含独有信息时，即使两句并非紧邻，也按整簇删除处理。不得留下中间草稿、局部重说或倒计时。
- 规则 4 仍用于精确删除与正文黏连的口令本身。若后一版不能独立表达、前一版含独有信息，或语义无法确认，则不扩大删除范围，交由审核页决定。

（学于 6月9日 印度 2026-08-13；已确认；细化于 飞书20260812-150445 2026-08-13；已确认）

### 6. 正式成片字幕展示层（仅显式选择）

- 只有用户明确选择「正式成片字幕」或同义展示风格时，才启用独立展示层；它不改变原始 ASR 保真稿，也不替代事实核验或人工批准。
- 在该展示层中，对已确认的术语与数字统一采用成片写法：`AI / IT / TCS` 大写；千位数字按 `2,830`、`23,460` 分组；书名和引用可使用《》与“”。
- 用户未显式选择时，保留默认 ASR 保真字幕风格；不得因“看起来更正式”而自动启用大小写、标点或数字展示改写。

（学于 6月9日 印度 2026-08-13；已确认）

### 7. 指代对象决定「他 / 它」

- 国家、市场、企业、机构等非人格主体使用「它」；实际人物按性别及原话使用「他 / 她」。
- 仅在上下文唯一明确时做此类字幕纠错；对象存在歧义时保留 ASR 原文，并列入不确定清单，不凭主观猜测替换。

（学于 6月9日 印度 2026-08-13；已确认）

### 8. 表达真实先后关系的「然后」必须保留

- 「然后」若表达“先 A 后 B”的真实时序、操作顺序或“做了 X 然后才 Y”的因果，必须保留；不能因为它位于句首、句中或重复出现就自动删除。
- 自动口癖层一律不处理「然后」。只有人工语义判断已明确它完全无功能、删后不损失时序、因果、转折或口播节奏时，才可作为审核候选；无法确认时保留。

（学于 6月9日 印度 2026-08-13；已确认）

### 9. 不以“低价值铺垫”作为默认自动删减

- 自动剪辑只处理可确认的录制废料：倒数口令、口误、假起句、残句和已确认的重录簇。
- 不得因一段内容被判断为“铺垫多”“信息密度低”“不够精彩”而自动删除、压缩、改写、调序或下沉。此类结构编辑必须由用户明确提出，且与口误清理分开执行。

（学于 6月9日 印度 2026-08-13；已确认）

### 10. 正式展示层只规范已确认的事实型数值

- 仅在用户显式选择正式成片字幕、且文本已纠错或对应事实修改已获批准时，规范可识别的事实型数值：金额、数量、比例、年份、编号和明确的时长等；可改为阿拉伯数字、保留单位，并为四位及以上数字加千分位。
- 不能把自然语言结构机械数字化，例如「一边」「第一个」「一个人」「一套」以及其他非事实数量表达；模糊量词、单位或数值存在声学/事实不确定时，保持原样并进入人工核验，不猜测补全。
- 数字、单位和千分位只能建立在已纠错或已核验的文本上；展示规范不得改变数值、单位、日期、比例或说话人观点。

（学于 6月9日 印度 2026-08-13；已确认）

### 11. 用户标定的题眼在主字幕中单独成行

- 题眼来自用户明确给出的标题、选题 brief 或脚本文案语义，不从画面是否存在大字标题推断。
- 在开头或章节性转折的自然语义位置，题眼的原文出现可优先独立成行以获得强调；不得凭空新增、重复题眼，也不生成第二条花字轨。
- 若题眼后带有「啊」等有功能的原话成分，必须随原文保留，不能为了做题眼行而吞字。

（学于 6月9日 印度 2026-08-13；已确认）

### 12. 主字幕断行采用全局语义优化

- 断行先枚举一个句群内的候选边界，再按总代价选择，而不是从左到右贪心切行。不可拆语义单元内部视为极高代价；残片行、字数偏离目标、并列结构断法不一致和跨卡语义反转视为高代价。
- L1 语义单元（否定/程度范围/情态与中心谓语、数字单位、专名等）不可拆；L2 读感单元（无“的”的紧密复合、动宾、动补、长定语和介词框架）优先保持，但在超宽时可在其高层边界降级断开。带「的」的长定语允许在「的」之后断开；并列项之间是高质量断点，单项内部不可拆。
- 强连贯单元可以跨行但不应跨字幕卡；不得让上卡已自洽的判断在下卡被否定、反问、转折或让步推翻。若有时间轴，跨卡的语义悬置不应超过约 2 秒。
- 行宽按画幅、字号和安全区参数化；无交付 profile 时以 14 个中文字量为软上限、7–10 为目标。排比/列举保持平行断法；双行卡在不违反语义约束时优先上行略长于下行。

（学于 6月9日 印度 2026-08-13；已确认）

### 13. 自动字幕只产出主字幕轨

- 自动字幕默认只输出与原话一一对应的主字幕轨；不复制硬数据、实体或关键词生成花字/强调轨，也不从正文抽碎片拼冷开场。
- 花字、金句放大、蒙太奇、冷开场和主轨之外的结构提炼属于显式的视频编辑需求，不能由字幕格式化默认触发。

（学于 6月9日 印度 2026-08-13；已确认）
